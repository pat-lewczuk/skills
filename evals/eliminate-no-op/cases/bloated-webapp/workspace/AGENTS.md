Install dependencies with `pnpm install`. The dev server is `pnpm dev` on port 4310 — not
3000, because the legacy proxy still owns 3000.

## Code style

- Use 2-space indentation.
- Use single quotes for strings.
- Always run the formatter before you commit.
- Never use the `any` type.
- Keep lines under 100 characters.
- Do not add comments that restate what the code on the next line does.
- Do not add a try/catch that only logs and re-throws.
- Extend the existing component rather than adding a `*V2` variant beside it.
- Imports must be sorted alphabetically.

## Understanding React

React is a JavaScript library for building user interfaces. It uses a component-based
architecture where each component manages its own state. When state changes, React
re-renders the component and its children.

Hooks let function components use state and lifecycle features. `useState` returns a
stateful value and a setter. `useEffect` runs a side effect after render, and its
dependency array controls when it re-runs. `useMemo` caches an expensive computation
between renders. `useCallback` returns a memoised callback.

Props flow down and events flow up. Lifting state up means moving shared state to the
closest common ancestor. Context provides a way to pass data through the tree without
threading props through every level.

Server components run on the server and can be async. Client components need the
`'use client'` directive at the top of the file.

## State management

All server state goes through React Query. Never fetch in a `useEffect`.

Client-only UI state uses `useState` or `useReducer`. There is no global store.

## Data access

Every query goes through `src/lib/db.ts`. Do not import the Postgres client directly
anywhere else — connection pooling is configured in that one module.

Never write real customer data into test fixtures, even anonymised. Use the generators in
`src/test/factories.ts`.

Do not commit anything from `secrets/` or any file matching `*.local.env`.

## Testing

- Write tests for your code.
- Unit tests: `pnpm vitest run --project unit`.
- E2E tests: `pnpm playwright test --project chromium-desktop`.
- E2E tests require the dev server running on 4310 first.
- Tests should be meaningful and provide good coverage.
- Aim for high test coverage where appropriate.

## Commit conventions

Commit messages follow the conventional commits spec.

```
feat(cart): add quantity stepper

Longer body explaining why the change was needed. Wrap at 72 characters.
Reference the ticket at the bottom.

Refs: STORE-1481
```

The format is `type(scope): subject`, where type is one of feat, fix, chore, docs, refactor,
test, or perf. The scope is the package or feature area. The subject is imperative mood and
lowercase, with no trailing period. The body explains why. The footer references the ticket.
For example, `feat(cart): add quantity stepper` is a valid subject line and
`Added a stepper to the cart.` is not, because it is past tense and capitalised.

## Migrations

Migrations live in `migrations/` and run with `pnpm db:migrate`.

If a migration fails partway through, do not retry it. Restore from the snapshot in
`migrations/snapshots/` first, because our migrations are not idempotent.

## Legacy code

Do not modify anything under `packages/legacy-billing/` — it is vendored from the old
monolith and regenerated by a nightly job. Changes there are silently reverted.

## Redux migration

We are migrating from Redux to React Query. New code should use React Query. Old Redux
slices are being ported one at a time — do not add new slices.

## Testing again

Remember to run the unit test suite with `pnpm vitest run --project unit` before you push.
